MiniCode: 面向代码仓库的本地代码智能体执行框架

MiniCode 面向代码仓库长链路开发任务，覆盖模型接入、工具调用、上下文治理、结构化记忆、 运行审计与评测闭环，重点解决多轮任务中的上下文膨胀、重复文件读取、工具误调用和结果不可复现问题。

GitHub Repository
Python Agent Harness Tool Calling Context Engineering Memory Retrieval Prompt Cache Benchmark

Overview

项目围绕“本地可回放的代码 Agent 执行链路”展开：在统一的 Agent Harness 中管理模型后端、 工具执行、会话状态、上下文预算、记忆召回、运行工件和评测结果，让一次长链路任务不仅能跑通， 也能被复盘、比较和回归验证。

2 类模型后端接入
7 类工具统一调用
86 条自动化测试

Architecture

MiniCode 的核心是 Agent Harness：它把模型请求、工具调用、状态管理和工件落盘放在同一条可审计链路里， 支持 2 类模型后端、7 类工具和 3 类运行工件。

  1. Model Runtime 统一不同模型后端的输入、输出和运行参数。
  2. Tool Calling 标准化工具 schema、参数校验、执行结果和错误反馈。
  3. Context Manager 管理仓库上下文、任务摘要、预算裁剪和 prompt cache。
  4. Memory Layer 分层维护任务摘要、文件摘要和会话笔记，并按相关性召回。
  5. Audit & Benchmark 落盘 trace、attempts、tool steps、failure category 和评测汇总。

Context

针对代码仓库长链路任务中的 prompt 膨胀问题，MiniCode 设计了分层上下文管理与预算裁剪机制。 在 12 组真实长上下文配置上，平均 prompt 长度从 6964 压缩到 5418。

Memory

通过任务摘要、文件摘要和会话笔记的分层管理，结合 freshness 校验与记忆召回， MiniCode 减少了多轮任务中的重复读文件和重复工具调用。

  • 在 12 个真实记忆依赖任务中，重复读文件次数从 8 次降至 3 次。
  • 平均重复工具调用次数从 0.67 降至 0.25。
  • 任务正确率从 66.7% 提升至 100%。

Governance

项目构建标准化工具调用与安全边界，覆盖参数校验、工作区隔离、高风险审批、只读委派、 重复调用拦截和敏感信息脱敏。

  • 在 11 个真实治理场景中，结构化记录 3 次路径逃逸拦截。
  • 记录 5 次无效参数拒绝。
  • 记录 2 次重复调用拦截。

Evaluation

MiniCode 建立固定 benchmark 与运行审计体系，自动汇总 pass rate、attempts、tool steps、 failure category 和 trace，支持不同模型后端的回归对比。

Internship Project · BioFord ChatBI

ChatBI 智能报表与多 Agent 分析系统

这是我在深圳津渡生物科技有限公司实习期间参与的核心项目：把自然语言问题转化为可执行的数据分析流程， 通过多 Agent 编排完成选表、SQL 生成、结构校验、执行反馈、图表生成和 Markdown 报告输出。

项目介绍文档 项目评测文档
Multi-Agent Text2SQL SchemaGraph Vector Retrieval Benchmark

Overview

项目面向组内生物医药业务数据分析场景，希望让使用者通过自然语言提出分析需求，系统自动完成数据查询、 可视化和报告生成。与单次 Text2SQL 不同，ChatBI 更像一个可追踪的分析流水线：每一步 Agent 都有清晰职责， 并通过事件回传、日志追踪和重试机制保证过程可解释、可诊断。

24 业务表本地 SQLite 可复现评测环境
500+ Text2SQL / Chart benchmark 样例
93.92% runtime schema pruning SQL 执行成功率

Architecture

系统采用 Orchestrator-BaseAgent 编排架构，由 Orchestrator 统一管理任务状态、上下文传递、 Agent 生命周期和事件输出，各 Agent 专注完成单一阶段。

  1. Planner 拆解用户意图，确定查询和分析计划。
  2. SQLGen 基于裁剪后的 schema 子图生成 SQL。
  3. Judge 对 SQL 结构、语义和结果风险进行评审。
  4. Execute 执行查询，并把错误或结果反馈给上游 Agent。
  5. Visualize / Report 生成图表配置和多方向 Markdown 报告。

My Work

  • 参与后端研发，拆分 Planner、SQLGen、Judge、Execute、Visualize、Report 等 Agent， 统一 Agent 生命周期、日志追踪与事件回传。
  • 构建 SchemaGraph 缓存、向量检索选表与动态子图裁剪机制，降低大 schema 场景下的上下文噪声。
  • 设计“SQL 生成 - 结构校验 - Judge 评审 - 执行反馈 - 有界重试”闭环，并通过 CTE 物化中间结果支撑多步分析。
  • 搭建本地 SQLite 可复现评测环境与 500+ benchmark，设计 no / full / runtime / gold graph 对比实验。

Evaluation

在评测中，runtime schema pruning 只保留约 11.63% 相关字段上下文，达到 93.92% SQL 执行成功率与 61.11% 结果正确率。接入完整 Agent 链路与 Judge / Retry 后，端到端结果正确率约 66%。

这个结果说明，针对业务库的 schema 裁剪和 Agent 反馈闭环，比单纯把完整 schema 塞进模型上下文更适合 可复现、可诊断的企业数据分析系统。
